# 有内鬼（原 TempRoom）

## 名字由来：有内鬼，取消交易 🎬

> 2002 年，陈永仁在天台告诉刘建明：「我想做个好人。」
> 刘建明说：「好，给警察一个机会。」
> 陈永仁抬头看见监视器，说出那句改变华语影史的台词：
> **「有内鬼，终止交易。」**

这句话为什么能流传 20 年？因为它精准击中了所有人的一个隐秘心理：

**——你有没有过这种时刻：一个电话销售加你微信，你不好意思拒绝，聊了 30 分钟才发现根本不想合作。你想拉黑他，但「加了又拉黑」更尴尬；你想不回消息，但对方还在不停地发。你被困在一个「临时沟通」里，进退两难。**

微信的设计哲学是「永不丢失关系」，但很多时候你**根本不想和这个人产生关系**。你只需要一个「协商窗口」——聊成了自愿加好友，聊崩了**一键取消交易，数据立即清空，谁也不欠谁**。

「有内鬼」就是为这个场景而生的：
- 你是那个接电话的客户 → 你是陈永仁，随时可以说「有内鬼，取消交易」，点一下，一切归零
- 你是那个发项目说明书的人 → 你是刘建明，你需要一个临时入口接收咨询，不想加微信、不想沉淀社交关系
- 或者你是线下活动的组织者 → 你只需要一个能扫码加入、到期自动解散的临时群

**有内鬼**——发现不对劲就终止，聊完即焚，不沉淀任何社交关系。

## 项目定位
临时沟通协商窗口：双向平等、聊完即焚、零社交沉淀。开源验证项目，不是商业产品。

## 技术栈
- 后端：Node.js（Express + ws），优先快速迭代
- 存储：Redis，房间元数据和消息存 Redis，key 设 TTL
- 登录：优先支持 OAuth 2.0 / OpenID Connect 标准渠道，MVP 先上 **GitHub OAuth**（开发者友好、不需要企业资质），后续按需求增加微信网页授权 snsapi_base、微博 OAuth；存储 OpenID + OAuth 返回的昵称和头像（仅用于会话内展示，不做跨会话关联）
- 前端：单页 HTML + 原生 JS，移动端优先，微信内置浏览器可正常打开
- 部署：提供 docker-compose.yml，AppID/Secret 通过环境变量注入

## 第一版只做这些（核心闭环）
1. OAuth 登录（MVP 先上 GitHub，后续加微信/微博），存储 OpenID + 昵称 + 头像（仅会话内展示）
2. 创建房间：事由名称、有效期（预设 1h/6h/24h/3d/7d + 自定义），**人数不限**
3. 生成短链接，复制分享
4. 对方点链接 → OAuth 登录 → 直接进房，无需额外确认
5. WebSocket 实时文字聊天，顶部常驻倒计时
6. **任何成员点击「结束会话」→ 二次确认 → 房间立即销毁，所有人断开**（双向平等终止权）
7. 到期前 1h/10min/1min 三级提醒；TTL 到期自动销毁（兜底机制）
8. 任一方可导出 Markdown（昵称 + 时间戳 + 头像展示名，不含 OpenID 等 OAuth 身份标识）
9. 销毁后不发任何后续通知；仅保留脱敏审计日志（房间ID、创建时间、销毁时间、人数、销毁触发方式），不含聊天内容

## 明确不做
- 不加好友、不建群、不提供对方资料页
- 不做历史会话列表（只显示进行中房间和创建入口）
- 不做已读回执、在线状态
- 不存储 OAuth 身份用于跨会话关联（昵称和头像仅在当前会话展示，销毁后清除）
- 不提供一键跳转微信或复制微信号
- 不阻止截图（截图无法技术阻止，产品只降低「对话长期残留」风险）

## 核心概念区分
- **退出会话**：成员主动离开房间（关闭页面、返回首页等），会话本身继续存在，剩余成员不受影响
- **结束会话**：任何成员点击「结束会话」并二次确认，触发**立即销毁**——所有成员断开、数据清零、房间码/链接失效。相当于「有内鬼，终止交易」

## 安全边界（写进 README）
- 全站 HTTPS
- 聊天内容只存 Redis 并设 TTL，不落持久库
- 导出文件即时生成返回，不留存
- README 声明：本产品用于隐私友好的临时沟通，不构成合规涉密通信方案，不替代 NDA 或正式合同

## 交付要求
- 先交付可运行的最小闭环（上面 1-9 条），不追求完整
- README：本地启动、docker-compose 用法、OAuth 配置说明、已知限制
- 代码按 OAuth / 房间 / WebSocket / 导出 四个模块分开
- 许可证：AGPL-3.0

## 已知风险（README 标注）
- 微信内置浏览器对第三方 OAuth 回调可能有拦截，需实测
- 微信 snsapi_base 网页授权需已认证服务号，个人主体可能拿不到
- 截图无法技术阻止，产品只降低「对话长期残留」风险
